# Disposable cashier-to-day-close infrastructure

Use only [the guarded launcher](../../scripts/test-cashier-day-close.ps1) with `-ConfirmDisposableInfrastructure`. This dedicated topology provisions ten application databases/runtime roles (Platform Directory, Restaurant, Authorization, Catalog, Inventory, Kitchen, Order, Payment, POS and Reporting), a separate Keycloak database and RabbitMQ. PostgreSQL 17 uses tmpfs, Keycloak 26.7.0 imports the generated realm, and RabbitMQ 4 carries actual Order publications. All published listeners bind to IPv4 loopback; run-owned credentials and identities are generated and removed with the exact project.

The shared launcher starts ten service APIs and one published Customer BFF. Order and POS use the acceptance-only real-entry-point clock host; the other service hosts retain normal system clocks. Reference setup creates no financial/state-transition records. See [commands, clock boundary, evidence and cleanup](../../docs/Deployment/Cashier-Day-Close-Acceptance.md). This is disposable acceptance infrastructure, not a production deployment or midnight certification.
