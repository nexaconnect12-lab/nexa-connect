# Disposable cashier-to-day-close infrastructure

Current cutoff/approval/settlement mode uses Order 18 / Payment 17 / POS 18 / Authorization 13 and compatibility 0.32.0. It requires sixteen distinct real-OIDC browser passes, including temporary source fence preparation/cancellation and durable settlement receipt/replay/restart with workload-only source decisions. Six Authorization persistence cases and exact cleanup remain required. Prior fifteen-scenario preparation evidence remains historical; current execution is recorded in [settlement evidence](../../docs/Architecture/Evidence/Day-Settlement-Acceptance.md). Original non-cutoff modes retain their schema targets.

The preceding cutoff-only mode used source revision protocol 2 (Order 13 / Payment 12 / POS 10, compatibility 0.26.0) and required exact-set Reporting delivery proof. Prior 0.25.0 acceptance records remain historical. The original non-cutoff cashier/preparation modes retain their pinned schemas. Revision-only execution remains historical; current seal execution is recorded separately under docs/Architecture/Evidence/Day-Close-Seals.md.

The [joined cashier-to-cutoff launcher](../../docs/Deployment/Cashier-Day-Cutoff-Acceptance.md) reuses this ten-context topology under its own generated project and newer schema targets. It adds an optional generated accountant password to the disposable Keycloak environment; existing launchers default that unused setting. No production topology/permission change is introduced.

Use [the guarded cashier-to-day-close launcher](../../scripts/test-cashier-day-close.ps1) or [the cutoff launcher](../../scripts/test-cashier-day-cutoff.ps1) with `-ConfirmDisposableInfrastructure`. This dedicated topology provisions ten application databases/runtime roles (Platform Directory, Restaurant, Authorization, Catalog, Inventory, Kitchen, Order, Payment, POS and Reporting), a separate Keycloak database and RabbitMQ. PostgreSQL 17 uses tmpfs, Keycloak 26.7.0 imports the generated realm, and RabbitMQ 4 carries actual Order publications. All published listeners bind to IPv4 loopback; run-owned credentials and identities are generated and removed with the exact project.

The shared launcher starts ten service APIs and one published Customer BFF. Order and POS use the acceptance-only real-entry-point clock host; the other service hosts retain normal system clocks. Reference setup creates no financial/state-transition records. See [commands, clock boundary, evidence and cleanup](../../docs/Deployment/Cashier-Day-Close-Acceptance.md). This is disposable acceptance infrastructure, not a production deployment or midnight certification.
