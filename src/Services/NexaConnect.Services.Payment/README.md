# Payment Service

Owns payment intents and idempotency keys. `POST` and `GET /api/payment/v1/intents` provide the first payment-intent API. Set `Persistence:Provider=PostgreSQL` and `ConnectionStrings:Payment` to use the parameterized PostgreSQL repository; development defaults to the in-memory adapter. `IPaymentProvider` and `HttpPaymentProvider` provide the provider boundary for authorization without accepting raw card data; provider transaction persistence and capture orchestration remain application work.

Customer Portal payment-intent create and read calls carry the shared tenant-context headers (`X-Nexa-Portal-Request: customer`, `X-Nexa-Organization-Id`, and `X-Nexa-Application-Code: nexa_connect`). Payment validates active organization access through Platform Directory, resolves the referenced Order and requires its organization/branch to match, then validates the Restaurant-owned restaurant/branch scope. Configure `Services:PlatformDirectory`, `Services:Order`, `Services:Restaurant`, and the dedicated `nexaconnect-payment-service` `WorkloadIdentity` credentials. Refund, capture, and broader financial approval authorization remain future work.
