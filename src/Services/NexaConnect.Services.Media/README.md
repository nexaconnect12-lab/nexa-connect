# Media service

This service owns media metadata and the S3-compatible object lifecycle. Apply Media migrations 1 and 2 and configure `ConnectionStrings__Media`, both service dependencies, and `MediaStorage__ServiceUrl/Bucket/AccessKey/SecretKey`. Local MinIO is exposed at `http://localhost:9100` (console `http://localhost:9101`).

The write lifecycle is a development preview, not approved for untrusted production uploads. The checksum is caller-declared metadata rather than a provider-proven digest. Content quarantine, Catalog-owner validation, quotas, expired-session cleanup, least-privilege local credentials, and durable reconciliation are still required. Metadata is marked deleted before best-effort object removal, preventing stale versions from deleting live bytes but allowing an orphan on storage failure.

`GET .../assets` lists up to 500 rows. `POST .../uploads` creates a ten-minute presigned PUT for JPEG, PNG, or WebP up to 10 MiB. Send the signed content type and `x-amz-meta-sha256`, then call `POST .../{id}/complete`; Media compares size and client-declared checksum metadata. `GET .../{id}/download` returns a five-minute signed URL and `DELETE .../{id}?expectedVersion=` removes the object and soft-deletes metadata. Malware scanning, variants, owner validation, and orphan reconciliation remain follow-up hardening.

Service name: `nexaconnect-media`. Query the safe `Customer media authorization denied` event by `correlation_id`. Tokens, object keys, checksums, and filenames are not logged by that event.
Dependency rejection also emits `Media organization access dependency rejected request`. Authorization returns `403`; invalid requests return `400`, missing assets `404`, and expired/stale lifecycle transitions `409`. Database, storage, and dependency failures fail closed. Verify with `dotnet build src/Services/NexaConnect.Services.Media/NexaConnect.Services.Media.csproj` and the `MediaManagementTests`, then apply both migrations before an authenticated smoke test.
