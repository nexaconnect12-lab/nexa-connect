# Media service

This service owns media metadata and the S3-compatible object lifecycle. Apply Media migrations 1 through 3 and configure `ConnectionStrings__Media`, both service dependencies, and `MediaStorage__ServiceUrl/Bucket/AccessKey/SecretKey`. Local MinIO is exposed at `http://localhost:9100` (console `http://localhost:9101`).

The write lifecycle remains a hardened preview pending full production acceptance. Upload signatures bind the S3 SHA-256 checksum header and completion reads the provider-returned checksum. Completion also reads at most the declared 10 MiB, checks the declared JPEG/PNG/WebP signature, and scans the bytes with ClamAV. Unsafe content is transactionally marked `quarantined`, emits `media.asset.quarantined`, is never downloadable, and enters the durable object-deletion queue. Catalog owner existence is verified through a dedicated workload call before signing. Quotas, expired-session cleanup, least-privilege local credentials, and generated variants remain required. Delete atomically soft-deletes metadata, writes audit/outbox state, and enqueues a migration-3 deletion job. `MediaObjectDeletionWorker` removes objects idempotently and retries storage failures with structured events.

`GET .../assets` lists up to 500 rows. `POST .../uploads` creates a ten-minute presigned PUT for JPEG, PNG, or WebP up to 10 MiB. Send the signed content type and `x-amz-checksum-sha256`, then call `POST .../{id}/complete`; Media compares provider-returned size and SHA-256 with the declaration before type-signature and malware inspection. A rejected completion returns `409` after quarantine. Scanner unavailability fails closed and returns `5xx`, leaving the upload pending for retry. `GET .../{id}/download` returns a five-minute signed URL only for ready assets. `DELETE .../{id}?expectedVersion=` atomically soft-deletes metadata and queues asynchronous object removal; previously issued signed URLs can remain usable until their five-minute expiry or provider deletion.

Set `MediaSafety__MalwareScanEnabled=true`, `MediaSafety__ClamAvHost`, and `MediaSafety__ClamAvPort` in production; startup rejects production configuration with scanning disabled. Local Compose exposes ClamAV only on `127.0.0.1:3310`. Run real-provider acceptance with `NEXA_MINIO_ACCEPTANCE=1` and `NEXA_CLAMAV_ACCEPTANCE=1` after starting MinIO, `minio-init`, and ClamAV; these tests are opt-in and use the local acceptance credentials.

Service name: `nexaconnect-media`. Query the safe `Customer media authorization denied` event by `correlation_id`. Tokens, object keys, checksums, and filenames are not logged by that event.
Dependency rejection also emits `Media organization access dependency rejected request`. Authorization returns `403`; invalid requests return `400`, missing assets `404`, and expired/stale lifecycle transitions `409`. Database, storage, and dependency failures fail closed. Verify with `dotnet build src/Services/NexaConnect.Services.Media/NexaConnect.Services.Media.csproj` and the `MediaManagementTests`, then apply all three migrations before an authenticated smoke test.

Deletion operations back off exponentially for ten attempts. Monitor with `SELECT asset_id,attempts,next_attempt_at_utc,last_error FROM media_object_deletions ORDER BY next_attempt_at_utc;`. Rows at ten attempts require operator investigation; after correcting storage, reset `attempts=0,next_attempt_at_utc=now(),last_error=NULL` for the reviewed asset. Migration 3 is a startup prerequisite; drain the table and stop Media before downgrade.
