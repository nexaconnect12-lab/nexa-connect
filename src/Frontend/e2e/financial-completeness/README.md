# Financial completeness browser contracts

Run `npm run test:e2e:financial-completeness` from `src/Frontend`. Chromium must already be installed (`npx playwright install chromium` when preparing the test environment). The suite starts a test-owned in-process Vite server at `127.0.0.1:5181`, refuses an occupied port and closes the server in global teardown. It avoids relying on Windows child-process tree termination. Traces, screenshots and videos are disabled; failure context contains synthetic fixtures only.

Nine synthetic BFF browser cases cover the three recorded statuses, source/check times and separate inventories, identical sales/observation UTC windows, explicit reload, denied/unavailable reads, filter and tenant clearing with delayed responses, closed/31-day validation, mismatched-scope rejection and the 25-second timeout with late-response suppression and subsequent reload recovery. No reconciliation, replay or other financial write is sent. Browser fetch-level tests are supplemented by .NET `CustomerFinancialCompletenessBoundaryTests` for real BFF session/cookie, current membership, sanitized errors and outbound correlation/tenant propagation with stubbed HTTP dependencies.

This does not prove a joined live OIDC/BFF/Reporting/database/browser deployment, create an observation, or certify settlement/global completeness. Apply Reporting 20 (existing Payment 10/Order 11 recovery prerequisites), record a check through restricted operator tooling and complete an environment-specific portal smoke test before production rollout.
