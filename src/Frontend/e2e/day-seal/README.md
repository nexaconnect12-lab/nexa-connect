# Day-seal browser verification

The current 14-case Chromium suite also covers reviewed approval before finalization preparation, CSRF cancellation, exact retry after unavailable response and read-only accountant/filter boundaries. Fixture proof timing is explicit; this suite is separate from real source/API acceptance.

Run `npm run test:e2e:day-seal` from the frontend workspace. Fourteen synthetic Chromium scenarios use the actual portal with intercepted BFF responses: the seven seal cases cover reviewed version/CSRF commands, journaled-change invalidation, missing review, accountant read-only controls, malformed proof, uncertain command replay/filter reset and baseline/current/delta comparison. Four approval cases add explicitly reviewed seal gating/CSRF, exact uncertain-operation retry, accountant denial/filter clearing and immutable history across unverified/superseded validity. Three finalization-preparation cases cover reviewed approval, cancellation/retry and read-only scope boundaries. Trace/screenshot/video are disabled. These do not certify real identity or source/broker execution; see [seal evidence](../../../../docs/Architecture/Evidence/Day-Close-Seals.md) and [approval verification](../../../../docs/Deployment/Day-Close-Approvals.md).
