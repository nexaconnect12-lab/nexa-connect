# Day-seal browser verification

Run `npm run test:e2e:day-seal` from the frontend workspace. Eleven synthetic Chromium scenarios use the actual portal with intercepted BFF responses: the seven seal cases cover reviewed version/CSRF commands, journaled-change invalidation, missing review, accountant read-only controls, malformed proof, uncertain command replay/filter reset and baseline/current/delta comparison. Four approval cases add explicitly reviewed seal gating/CSRF, exact uncertain-operation retry, accountant denial/filter clearing and immutable history across unverified/superseded validity. Trace/screenshot/video are disabled. These do not certify real identity or source/broker execution; see [seal evidence](../../../../docs/Architecture/Evidence/Day-Close-Seals.md) and [approval verification](../../../../docs/Deployment/Day-Close-Approvals.md).
