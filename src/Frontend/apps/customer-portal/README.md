# NexaConnect Customer Portal

Phase 8 provides the independently buildable tenant-scoped Customer Portal context/navigation shell. Authentication is owned by `NexaConnect.CustomerBff`; the browser receives only opaque cookies and selects one organization plus enabled product from `/bff/customer/access`. `/tenant` and `/features/*` revalidate the protected server-readable selection.

The portal includes profile, product switching, memberships, branches, configuration, Reporting dashboards/sales/activity preview, and Media-owned list/upload/original/variant download/delete. Uploads go directly to the signed S3-compatible URL and are completed through the BFF. Media verifies provider checksum/size, validates the image signature, scans with ClamAV, enforces pending-count and original-byte organization quotas, cleans expired sessions, and asynchronously creates thumbnail/display WebP variants. Generated variants are excluded from the original-byte quota and require separate bucket-capacity monitoring.

The organization-wide Branch and Media lists currently require an organization-scoped `tenant-admin` product assignment. A restaurant-scoped `store-manager` assignment does not satisfy those list decisions because the current list requests carry no restaurant filter.

Run `npm run dev --workspace @nexaconnect/customer-portal` with `CUSTOMER_BFF_URL` set for local proxying. Run `npm run check`, `npm test`, and `npm run build --workspace @nexaconnect/customer-portal` from `src/Frontend`. Publishing the Customer BFF builds and embeds the SPA unless `SkipCustomerPortalBuild=true` is used after independently supplying verified assets.

For the same-origin Phase 8 development stack, trust the ASP.NET development certificate (`dotnet dev-certs https --trust`), start infrastructure with `docker compose up -d`, apply migrations 1-4 for Media and the current migrations for the other services, seed at least one organization-enabled Catalog product, build once, and run `scripts/run-phase8-development.ps1`. Pass `-Build` to build each application before launch. The script loads the ignored `.env`, rejects missing or placeholder secrets, forces ClamAV scanning on, enables PostgreSQL Catalog persistence and the RabbitMQ activity publishers/consumer, preserves separate Catalog and Media workload identities, starts Platform Directory, Authorization, Restaurant, Reporting, Media, Catalog, Customer BFF at `https://localhost:51829`, and Platform Admin BFF with its Product Owner Portal at `https://localhost:58627`, and waits only for bounded HTTP liveness before writing separate logs under `.runlogs/phase8`. Liveness does not prove Keycloak credentials, seed data, broker delivery, storage/CORS, scanner signatures, or tenant workflows; complete the authenticated functional smoke test afterward. It executes each built service DLL directly and records the exact service PID and start identity in ignored `.runstate/phase8`; `scripts/stop-phase8-development.ps1` validates and stops only those recorded service processes, including both portal BFFs, and retains state when cleanup is incomplete, while infrastructure containers remain running. Scanner-disabled development requires a separate manual Media launch.
