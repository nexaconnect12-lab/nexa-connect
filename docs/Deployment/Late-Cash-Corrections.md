# Late-cash correction rollout and operations

Coordinate matching Order/Payment/POS/Authorization, BFF and Portal binaries with **Order 19 / Payment 18 / POS 20 / Authorization 15**, compatibility **0.34.0**, Reporting 20 unchanged. The migration launcher defaults to 0.34.0; version compatibility does not itself choose schema targets. Order adds an authoritative original-tender read route using existing receipt/tender/outbox storage. POS 20 owns two new tables and the posting journal guard; Authorization 15 adds the posting grant. Stop old writers while applying the coordinated schema/application change. Existing unrelated historical migration levels remain documented at their introduction versions.

POS needs existing `Services:Order`, `Services:Restaurant`, `Services:Authorization`, Directory and POS hierarchy dependencies. The correlated `DayCutoffOrder` adapter forwards the **customer bearer** for original proof. Correlated `CorrectionRestaurant` uses the existing restricted POS workload token for business calendar only, through existing API audience issuance. BFF uses its existing POS client, session token storage and antiforgery. No new client, secret, worker or production clock setting is introduced.

`late_cash_corrections` uniquely binds organization/operation, work, original event, tender and Order; its primary key is organization/correction UUID. Same-owner FKs retain custody, exact review and original drawer. An organization/Restaurant/branch/posted-time/ID index supports day summaries. Separate audit rows retain actor and live amount Authorization UUID. UPDATE/DELETE/TRUNCATE is prohibited. Insert guards lock branch revision then case, verify exact committed scope/current review/unapplied cash/drawer/amount and current calendar interval, and the owning trigger advances revision plus posting-time journal in the same transaction. Application validates the same financial policy and verifies Order outside the transaction. Ledger/receipt, audit, journal and outbox roll back together.

Grant the POS runtime role SELECT/INSERT on its own `late_cash_corrections` and `late_cash_correction_audit`, plus existing outbox, financial revision/journal, custody/link/barrier/review reads and related drawer/store/shift/terminal reads. It needs no DDL, history UPDATE/DELETE/TRUNCATE or foreign database access. Migration owner installs functions/triggers. Authorization runtime retains its ordinary decision/assignment permissions. Source and ledger history must be backed up/restored together; cold deletion of original Order tender/outbox/receipt evidence prevents new verified posting, while stored exact correction retries remain available with live authority.

POS 20 downgrade refuses any retained correction; empty downgrade drops ledger/audit and restores the preceding fence classifier. Roll back correction schema before review/barrier schemas. Do not remove evidence to force downgrade. Authorization 15 downgrade removes posting role links and overrides; disable posting first. Existing grants may be customized through the live product policy. Before enabling posting, configure an applicable active `financial_approval_limits` role/subject row for the Restaurant, action `pos.day-close.late-cash.post`, THB and a reviewed maximum amount. Permission grants do not create a cap; a missing limit denies all postings. Currency/magnitude is server-derived and evaluated again on exact retry. The isolated acceptance fixture supplies its own bounded test cap and temporarily lowers it to prove denial; that cap is not a production default.

Query `service.name=nexaconnect-pos`, `nexaconnect-order` or `nexaconnect-customer-bff` with validated `CorrelationId` for `Cash correction`, `Tender evidence`, authorization denial, conflict and bounded unavailable category. Shared JSON/OTLP applies to all new HTTP adapters/routes. Never log amounts, bodies, identities/subjects, provider references, tokens, cookies or arbitrary headers. Durable business audit is separate from telemetry.

Outbox contract is `pos.late-cash-correction-posted.v1` / `PosLateCashCorrectionPostedV1`, containing original settlement/work/Order/tender/drawer references, exact reviewed version, posting date/interval, THB cash variance adjustment and normal event/correlation/occurrence metadata. Retain it even with publishing disabled; use the existing POS outbox configuration to publish. There is no Reporting consumer in this release, and settlement receipt or cash-close publications are not rewritten.

Run build, unit/architecture/BFF tests, `scripts/test-day-seals.ps1 -ConfirmDisposableInfrastructure`, frontend check/Vitest, sealed-day and end-of-day Chromium, and `scripts/test-cashier-day-cutoff.ps1 -ConfirmDisposableInfrastructure`. The expanded seventeen-case real-OIDC gate provisions only an additional branch/store/terminal/product reference plus scoped grants. Actual cashier commands create all financial state; a run-owned POS restart with consumer disabled holds the real broker delivery until settlement, then normal restart captures it. It exercises real review/preview/post, accountant and live posting revocation, dropped committed response, POS restart, exact retry and original receipt/cash preservation. The helper accepts only enumerated generated-child actions and is unavailable in production. See [execution evidence](../Architecture/Evidence/Late-Cash-Correction-Acceptance.md).
