# Settlement replay rollout, privileges and recovery

Deploy POS 23 / Reporting 22 with matching binaries at compatibility 0.38.0; Order 19, Payment 18 and Authorization 15 stay unchanged. The migration launcher defaults to 0.38.0. POS migration 23 adds `settlement_replay_runs` and `settlement_replay_attempts`, their ordering/selection/credential-attribution guards and immutable history. The catalog is 201 tables (POS 52 / Reporting 19). Empty 23→22→23 roundtrip succeeds; any retained replay run/attempt refuses downgrade. Use backup/forward recovery for audit history. Normal POS source and Reporting financial behavior remain ADR-034.

Build `src/Tools/NexaConnect.CashCloseReplay`. Inject `NEXACONNECT_SETTLEMENT_REPLAY_DB` with a POS-only connection and, for execution, `NEXACONNECT_SETTLEMENT_REPLAY_BROKER`. Optional `NEXACONNECT_SETTLEMENT_REPLAY_EXCHANGE` defaults to `nexaconnect.events`. Secrets belong in environment/secret store, not arguments or repository files. The tool [.env.example](../../src/Tools/NexaConnect.CashCloseReplay/.env.example) is a reference only, not loaded automatically. Shared client service name is `nexaconnect-settlement-replay`; optional `OTEL_EXPORTER_OTLP_ENDPOINT` enables export. The CLI has a ten-minute deadline and cancellation support.

Issue controlled least-privilege administrative logins for the approved scope. Preview needs database CONNECT, schema USAGE and SELECT on `branch_day_settlements`, `branch_day_settlement_decisions`, `branch_day_settlement_receipts`, `outbox_messages`. Execute additionally needs SELECT/INSERT on the two replay audit tables and their normal trigger execution. Do not grant source UPDATE/DELETE, migration/DDL privileges or Reporting credentials. Broker credentials need the reviewed exchange declaration/publication capability. Scope validation prevents cross-tenant selection, but this is not OIDC/RLS authority: access to the issued database/broker login is privileged, and the operator UUID is asserted attribution. `session_user` records the actual authenticated database login and cannot be overridden by the insert argument. Customers/accountants cannot invoke replay through the portal.

1. Inspect the protected ledger's missing/conflicting delivery and original POS history. Review exact organization/Restaurant/branch/business dates and authorized operator credentials.
2. Start the Reporting settlement consumer and verify durable queue, subscriber and **both** `pos.branch-day-settled.v1`/`.v2` bindings on the actual exchange. Initial readiness alone is not ongoing health. Confirm broadcast effects for other matching subscribers.
3. Preview without broker access:

```powershell
dotnet src/Tools/NexaConnect.CashCloseReplay/bin/Debug/net10.0/NexaConnect.CashCloseReplay.dll --settlements --organization <uuid> --restaurant <uuid> --branch <uuid> --from-date 2026-10-01 --to-date 2026-10-02 --limit 31
```

4. Retain the reviewed hash/count, then repeat identical selection with `--execute --operator <uuid> --reason retry --manifest <SHA256>` (or `rebuild`). A changed selection requires another preview. `rebuild` is an audit reason only; this mode does not drop/reset Reporting projections.
5. Inspect the returned run, started/confirmed attempts and actual login attribution. Recheck the exact authorized ledger after asynchronous consumption. Broker confirmation is not projection proof; a paused consumer can leave the ledger missing after CLI success.

Publication occurs outside the intent transaction. Response loss or process interruption can leave uncertain audit status. If a run row is absent, the intent did not persist; if present, inspect each started/confirmed pair. Never infer rollback from exit 1. Re-preview and execute a new run retaining original identities; Reporting deduplicates, and conflicts dead-letter without financial overwrite. Source disappearance/corruption or unknown schema blocks replay until legitimate history is restored. Do not manufacture a V2 event, new ID, changed timestamp or correction amount, or reset dispatcher flags. New source commits after the selected snapshot belong to a later preview.

Query safe `Settlement replay` logs under `service.name=nexaconnect-settlement-replay`; follow run UUID and original correlation. Inspect audit SQL using parameterized run/scope values. Logs/console expose no financial body, amount, credentials, tokens/cookies, personal fields or arbitrary headers; operator/login attribution remains in restricted audit tables.
