# Late-work review rollout

Coordinate **Order 19 / Payment 18 / POS 19 / Authorization 14**, compatibility **0.33.0**, with matching Customer BFF/Portal. Reporting remains 20. The current migration wrapper defaults to compatibility 0.34.0; schema targets are still discovered independently. Preserve ADR-029 barriers, original messages and recovery configuration. No new secret, identity client or configurable background worker is introduced.

Each source migration adds an opaque `work_id` to its existing immutable custody records, generates UUIDs for retained rows, uniquely indexes organization/work and indexes organization/received/work for pagination. Payload, fingerprint and original disposition remain unchanged. New review tables use primary key `(organization_id,barrier_id,work_id,version)`, unique `(organization_id,operation_id)` and same-owner custody/barrier FKs. Insert guards verify committed linked membership and consecutive versions under a per-case advisory lock; decision/reason/status check constraints backstop the source Domain. UPDATE/DELETE/TRUNCATE is forbidden.

Grant each source runtime role SELECT/INSERT on its own `source_late_work_reviews` alongside existing SELECT/INSERT custody/link permissions and SELECT barrier access. Runtime roles require no DDL, foreign schema access or UPDATE/DELETE/TRUNCATE on review history. Authorization 14 backfills review for tenant-admin/store-manager only; assignment defaults match. Its downgrade removes review role links and user overrides, so disable review routes first. Source downgrade refuses **any retained custody or review row** to preserve stable public work identities; empty downgrade/reapply is supported. Restore/back up custody, links, barriers and reviews together; use forward migrations after retained history.

POS retains existing `Services:Order`, `Services:Payment`, `Services:POS`, Restaurant/Authorization/Directory dependencies. The review facade uses correlated named `DayCutoffOrder`, `DayCutoffPayment`, `DayCutoffPOS` clients with the **customer bearer**, independently reauthorized at the owner. BFF uses its existing protected cookie, server-held token, antiforgery and correlated POS client. Old binaries can continue custody insertion via the UUID default, but exposing review should wait for all matching migrations, grants and applications.

Shared JSON/OTLP observability applies to HTTP paths. Query `service.name` = `nexaconnect-order`, `nexaconnect-payment`, `nexaconnect-pos` or `nexaconnect-customer-bff` and validated `CorrelationId` for `Late-work`, `authorization denied`, `conflict` and `unavailable` events. Failure events contain only bounded categories/statuses; never subjects, authorization decisions, bodies, provider IDs, amounts, tokens or arbitrary headers. No review event is published to Reporting in this slice.

Run `dotnet build NexaConnect.sln --no-restore`, unit/architecture tests, protected `CustomerLateWorkBoundaryTests`, `pwsh -File scripts/test-day-seals.ps1 -ConfirmDisposableInfrastructure`, frontend type/Vitest checks and `npm run test:e2e:day-seal`. The joined cashier-to-cutoff gate verifies current migrations and existing real-OIDC settlement behavior; synthetic queue browser cases and owning database cases cover review commands separately. See [execution evidence](../Architecture/Evidence/Late-Work-Review-Acceptance.md). Verified POS late-cash posting and a populated real-OIDC review-to-correction scenario are implemented separately by [ADR-031](../Architecture/Decisions/ADR-031-verified-late-cash-corrections.md). Other correction types, fiscal adjustment, report consumption and offline finalization remain planned.
